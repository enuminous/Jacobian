## 2. What the checked theorem actually says

The base field is the canonical algebraic closure of `ZMod 2`. In that field the map is

\[
P=x+x^2y+x^4+x^6y^2,\qquad
Q=y+x^5+x^6y+x^7y^2+x^8y^3.
\]

The terminal proposition uses the actual intermediate field generated by these P and Q inside the source fraction field. It includes determinant one, scheme-level étaleness, algebraic independence, field degree three, separability, finite separable degree three, an equivalence between geometric generic-fiber points and field embeddings, a three-point generic fiber, and noninvertibility. The terminal theorem has no added irreducibility argument supplied by the caller: it obtains that fact from `ActualIrreducibility.cubic_irreducible` before assembling the conjunction.

The two collision equalities in the terminal proposition are accompanied by inequalities separating (0,1) from the other two displayed points. The common image (0,1) is proved separately by `Generic.collision_value`; the third pair of points is also plainly distinct by its coordinates. We do not silently add these clauses to the printed terminal type.

## 3. Independent algebra checks

The audit's small standard-library implementation represents a polynomial in F₂[x,y] as a finite set of exponent pairs. Addition is symmetric difference; multiplication cancels equal monomials modulo two. It does not use Lean output as its arithmetic oracle.

It confirms the four partial derivatives, determinant one, the compact identities with r=1+xy, u=1+x³r and w=ru², the recovery identities, the hidden cubic identity, its derivative at w, the elimination identity, nonzero denominator polynomials, the origin and all three collision images. Removing the y term of Q breaks determinant one. Evaluating the integer derivatives at (1,0) gives determinant 5, exposing an invalid characteristic-zero extrapolation.

**All 18 checks passed.** Two are negative controls. These computations corroborate the polynomial certificate; they do not establish generic irreducibility, scheme-theoretic étaleness or the geometric-fiber equivalence. Those conclusions rely on the recorded formal replay and the inspected definitions. The absence of cycles in the local module import graph is also not a general proof of semantic noncircularity.

## 4. Reproduced harness findings

### F-01 — Axiom parser accepts ambiguous or wrong-target reports (medium)

**FAIL.** At the frozen harness commit, `scripts/check-axioms.py` accepts four invalid controls out of ten, while accepting both valid controls. The four false accepts are:

1. A different declaration prefixed `Other.` whose name ends in the target name.
2. Duplicate allowed-axiom reports.
3. An allowed report followed by a contradictory report containing `sorryAx`.
4. Unexpected text appended to an otherwise allowed report line.

The regex searches for a substring and accepts its first match. WEASEL's pinned bounded search independently reproduces all four witnesses in three repeats each. MONSTER rejects the robustness claim when any required input violates the frozen expected-acceptance condition. The exact fixtures and parser stdout/stderr are in [checks.json](evidence/checks.json).

**Impact:** this is an ambiguity/integrity gap if logs contain wrong-target, duplicate or mixed reports. It is not evidence that the real recorded KernelAudit log is forged or contradictory: its actual output contains one exact declaration and one allowed axiom report. **Next fix:** require one complete, anchored exact-name report; reject duplicate/conflicting declarations, unexplained trailing content and any unapproved axiom. Re-run the same controls plus a fresh real Lean report.

### F-02 — Reused extraction directory is not an exact source tree (medium)

**FAIL.** A harmless `AuditUnlisted.lean` sentinel was placed in an isolated replay source directory before the original fetch script ran. The verified ZIP extracted successfully and both digest gates passed, but the unlisted sentinel survived. `unzip -o` overwrites named members; digest manifests verify their listed paths without excluding extras.

The sentinel was not imported or executed, so the test does not show a changed theorem. It demonstrates that the script's integrity coverage is narrower than exact directory identity. Reused `.lake` state and old receipts require similar care. The post-build rehash covers five paths, not every Lean source or dependency checkout. **Next fix:** extract into a new temporary tree, check exact expected membership, isolate or explicitly authenticate build artifacts, and rehash all source inputs after replay. Avoid deletion of arbitrary caller-supplied paths.

The corrupted-archive negative control is **PASS**: altered bytes are rejected with exit 21 before extraction. The source authentication mechanism is real and useful.

### F-03 — Reproduction instructions contain a wrong directory (low; corrected in this publication)

The baseline README says `cd .replay/anc/lean`, but the extraction path is `.replay/source/anc/lean`. The index and README now give the actual path. This is a documentation correction; the audited scripts remain unchanged.

### F-04 — Reproducibility and supply-chain limits (observed limitations)

The workflow installs elan from mutable `master` and uses major-version action tags. The printed Lean version is recorded, while the script does not independently assert the executable identity or re-check every dependency's live Git HEAD after the build. The recorded run does show the expected versions and dependency checkout. Mathlib cache was enabled. A dependency-from-source, cache-free reproduction and fully immutable installer/action inputs remain UNRESOLVED.

The build has linter warnings, not proof errors. They do not change the exit-zero result. No attempt was made to alter Romy's proof source or suppress its warnings.

## 5. Anti-circularity, provenance and independence

The source's main dependency direction is sound on inspection: polynomial identities and recovery establish algebraicity; transcendence-degree reasoning establishes target algebraic independence; that independence enables transport of a generic irreducibility theorem to the actual target field; irreducibility then yields degree and separability; the geometric bridge connects embeddings to pullback sections. No use of the final degree-three result was found in the earlier independence proof. The conditional helper in `DegreeFromIrreducible` is not mistaken for the terminal result.

The published source digests and the author-hosted archive belong to the same provenance chain. Their mutual agreement establishes consistency, not independent authorship. The arXiv comparison confirms distribution identity; GitHub replay adds a different execution environment; local polynomial arithmetic adds a different implementation for a bounded part of the argument. These are complementary checks, not three independent mathematical discoveries.

ELEPHANT preserved the archive → CI → audit ordering and original provenance values. Its upstream `retention` metric was deliberately not used: the supplied implementation divides its current total by itself, so that number would not independently establish retained history. SALMON's trace reaches one common archive origin at depth two. Unit edge weights are explicit bookkeeping, not fitted confidence probabilities.

CIRCUS returns FAIL for the deliberately broader claim of unqualified independent certification of the whole paper, because a material semantic/external-formulation obligation remains unresolved. That gate does not refute the theorem. The audit is AI-assisted; no external human referee or author endorsement was obtained. No messages were sent to the author.

## 6. Novelty and scope

This repository faithfully replays an existing formalization. Its mathematical content is **identical/replayed**, not newly discovered by Monolithic or this audit. The independent arithmetic checks are corroboration of known identities.

The author's text identifies a preserved-coordinate reduction from Irit Huq-Kuruvilla's [three-variable characteristic-two construction](https://arxiv.org/abs/2607.20968). That is a related construction with a stated dimensional reduction, not evidence of wholly unrelated origins. The dimensional novelty/priority claim is **potentially novel but UNRESOLVED in this audit**; a comprehensive literature review was not performed and the original referenced paper was not fully retrieved here.

[Maubach and Rauf, arXiv:1507.02946](https://arxiv.org/abs/1507.02946), explicitly distinguish an alternative positive-characteristic formulation from Adjamagbo's. Accordingly, the phrase “Jacobian conjecture” must retain the exact formulation and characteristic. The conclusion must not be broadened to all positive-characteristic formulations or to the classical characteristic-zero problem.

Physical dimensional analysis is inapplicable to these abstract field variables; no SI-valued EFMW relation is being tested. A successful formalization cannot by itself establish a physical law, a customer result or an EFMW-specific advantage.

## 8. Minimal next steps and decision rules

1. **Harden the parser.** PASS only when both valid cases remain accepted, all ten invalid fixtures are rejected, and the actual fresh Lean log still parses. A false accept is FAIL; missing executable/log is UNRESOLVED.
2. **Use an exact isolated extraction/build tree.** PASS only when no unlisted source or stale receipt survives and the corrupted archive still fails. Retained unlisted input with an integrity PASS is FAIL.
3. **Repeat the exact source replay.** PASS requires source/manifest identity, explicit dependency revisions, exit-zero library/bridge/terminal checks and a unique literal axiom report. A proof error is FAIL; infrastructure failure is UNRESOLVED. Distinguish cached and cache-free runs.
4. **Obtain statement review.** Have an independent algebraic geometer compare the frozen external conjecture formulation, `FullCounterexampleStatement`, actual target field, étale predicate and generic-fiber section type. A weaker formal statement is FAIL; an incomplete review remains UNRESOLVED.
